# Repository working agreement

- Commit completed, relevant work as small cohesive milestones after appropriate verification.
- Include source code, migrations, tests, documentation, and configuration examples that belong to the milestone.
- Do not commit secrets, local `.env` files, credentials, generated build output, dependency directories, caches, or unrelated user changes.
- Before committing, inspect `git status`, run the relevant available checks, and summarize any checks that could not run.
- Use clear imperative commit messages that describe the delivered outcome.
- Do not push commits unless the user explicitly asks.
